# Ordered scripted simulation pipeline for the shared room runtime

The change replaces both room-specific legacy physics loops with one shared Rapier runtime and expands `AuthoritativeRoomCore` into the ordered Wave 17 pipeline. Stable-roster planning now completes before command application, controller state commits after Rapier and bounds recovery, and kickoff body/controller state has rollback. Fatal staged failures stop publication and dispose the world idempotently. The final projection boundary and authority-input contract remain incomplete, so task 5.6 is not ready to ship.

**Watch for:** **confirmed** — the fixed-step projection is discarded and rebuilt after the step index commits; **confirmed** — adapter schema projection is incomplete and non-atomic; **confirmed** — forged authoritative fields reject otherwise-valid controls instead of being ignored.

**Verdict**: NEEDS_CHANGES

## High-level view

Both room modes now construct `initializeAuthoritativeRapierWorld`; the core derives phase gates, synchronizes disabled edges, recovers bodies, grounds cars, plans every Stable_Roster_Order command before application, steps Rapier, bounds bodies, commits controller state, extracts events, reduces match flow, and validates a projection.

The validated projection is not retained. After `fixedStepsCompleted` increments, each adapter projects again, and the production projection callbacks repeat post-step recovery. The state actually published is therefore outside the fixed-step failure boundary.

Colyseus `GameState` remains owned by duplicated adapter methods that update fields incrementally and omit authoritative flow state including kickoff epoch and regulation-start status.

The V2 input boundary rejects a message that combines valid controls with forged authoritative values. That protects authority but violates the required control-only equivalence: those values must be ignored while valid controls still reach the next fixed step.

## Projection validation is discarded before the committed output is built

**Confirmed, high severity.** `executeOrderedFixedStep` calls and discards `createAuthoritativeProjection(this.fixedStepsCompleted + 1)` at `server/src/rooms/authoritative-room-core.ts:1136`; `advanceSimulation` then increments the index at `server/src/rooms/authoritative-room-core.ts:1042-1044`. The adapters subsequently call `projectAuthoritativeState()` at `server/src/rooms/arena-room.ts:271` and `server/src/rooms/custom-room.ts:385`, invoking projection again at `server/src/rooms/authoritative-room-core.ts:1146-1149`.

`projectCar` and `projectBall` repeat post-step recovery at `server/src/rooms/rapier-room-world.ts:255-270` after the ordered recovery at `server/src/rooms/authoritative-room-core.ts:1127-1129`. A later projection/schema failure can therefore occur after `fixedStepsCompleted` advances, and a zero-step callback can repair and publish bodies without a step-index change. Cache the first immutable projection as the committed artifact and make later transport/schema code consume it without body reads or recovery.

## Adapter schema writes omit live flow state and can partially apply

**Confirmed, high severity.** Quick and Custom mutate players before the ball and match fields with no rollback (`server/src/rooms/arena-room.ts:286-337`, `server/src/rooms/custom-room.ts:400-451`). An exception after an earlier assignment can expose a partially advanced Colyseus schema even though the core projection is complete.

Those methods never commit `goalResetStepsRemaining`, `regulationStarted`, `regulationCutoffResolved`, `kickoffEpoch`, winner/terminal data, or transition identity. Countdown completion changes `regulationStarted` and `kickoffEpoch` at `server/src/systems/match-flow.ts:680-690`, but the core projection type at `server/src/rooms/authoritative-room-core.ts:315-337` does not carry them. Move complete schema projection into one shared prepare/commit boundary.

## Forged authoritative fields suppress valid controls

**Confirmed, medium severity.** The new integration scenario combines a valid throttle/jump command with `position`, `blueScore`, and `team`, then expects `invalid-input` at `server/src/rooms/rapier-room-world.test.ts:159-166`. The strict normalization path rejects the whole message at `server/src/rooms/authoritative-room-core.ts:982-991`, so its valid controls never reach the subsequent step.

Requirements 1.1-1.3 require valid controls to behave like the control-only command while client-supplied transform/contact/inventory/score/team/phase values are ignored. Normalize known controls, discard authoritative extras, and compare forged-plus-controls against a control-only run.

## Coverage misses the exposed commit boundary

**Confirmed gap. Not tested:** projection failure after the staged projection succeeds, one-call projection/recovery in the production adapter path, atomic complete `GameState` application, kickoff-epoch/regulation-flag propagation, and forged-plus-controls equivalence. Validation otherwise passed: `npm run typecheck`, `npm run build -w server`, 45 focused room/runtime/scoring tests, and all three affected generated property suites.
