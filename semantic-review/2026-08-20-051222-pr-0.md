Property 10 combines generated planner cases with real Rapier car/ball recovery, while Property 19 compares paired authoritative cores after one Active Play step. The authority proof exercises the intended accept-controls/drop-extras contract and compares the complete next projection, world model, and wire snapshot. Property 10 has two blocking, **confirmed** gaps: correlated selectors leave non-finite branches unreachable, and its controller oracle proves only that a finite value emerged rather than that the required last-finite or defined fallback was used.

### Correlated generation leaves declared non-finite branches unreachable

**confirmed** — `generateFiniteBoundsCase` marks every index divisible by five as finite, while `generatedInput` chooses the axis to corrupt with `caseIndex % 5`. Index zero is throttle, so every case that would select throttle is switched to finite mode first; only steer, pitch, yaw, and roll can be corrupted (`finite-bounds.property.test.ts:288,408`). A regression in non-finite throttle handling can pass all 100 cases.

The tuning selector has the same defect. `INVALID_SCALAR_IDS` has 25 entries and uses `caseIndex % INVALID_SCALAR_IDS.length`, so finite-mode indices exclude entries 0, 5, 10, 15, and 20: `physics.fixedStepSeconds`, `car.mass`, `car.steering.normalGripRate`, `car.jump.holdDuration`, and `ball.mass`. The “at least 10” assertion at lines 920-924 cannot detect their absence. Decouple mode and field selection, then assert that every intended input component and scalar ID is represented.

### Controller recovery is checked for finiteness, not the mandated fallback value

**confirmed** — Generated cases supply `previousFiniteState`, malformed observations, and invalid tuning, but `assertControllerBounds` only requires finite plan numbers plus propulsion/air-angular bounds (`finite-bounds.property.test.ts:592-614`). It never compares an invalid observation with the matching prior finite component, missing-prior behavior with the defined default, or unaffected valid components before and after recovery.

A planner that ignores `previousFiniteState` and neutralizes an entire observation or control group to finite zeros still satisfies this oracle. An invalid tuning value can likewise resolve to an arbitrary finite value unless it violates a broad cap. Pair each malformed case with an explicit-fallback baseline, or assert the affected `nextFiniteState`/control outputs and unaffected-component preservation, before claiming Requirements 7.10-7.11.
