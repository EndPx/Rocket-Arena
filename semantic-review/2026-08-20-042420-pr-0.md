# Retained authoritative room pipeline and local camera presentation

Wave 0 replaces room-specific physics loops with one ordered authoritative pipeline, retains the exact immutable post-step projection for schema and V2 publication, and moves complete roster/ball/match application behind one schema preflight. It changes input ingress to discard forged authority while preserving valid controls, then adds local Ball/Car camera modes and a pure off-screen ball projection. The prior review's three blockers—discarded projection, partial schema writes, and forged-field suppression—are addressed. One camera-configuration boundary still violates the required finite all-or-nothing contract.

**Watch for:** **Medium · confirmed** — `validatedConfiguration` reads proposal properties once to validate them and again to store them, so a stateful getter can pass with a finite FOV and then commit `NaN`, making the camera projection matrix non-finite.

**Verdict**: NEEDS_CHANGES

## High-level view

`AuthoritativeRoomCore.executeOrderedFixedStep` now owns the complete stage order. It derives phase gates, synchronizes disabled input edges, recovers bodies, computes every grounding result and every Stable_Roster_Order command before applying any command, steps Rapier when permitted, performs post-step recovery, commits controller state, reduces match flow, and materializes one retained projection.

That artifact is identity-checked by `buildSnapshotV2` and consumed directly by both room adapters. `GameState.applyAuthoritativeProjection` constructs replacement player and ball candidates and validates roster, occupancy, timing, and terminal coherence before changing live schema references; input normalization independently extracts known controls and ignores forged extras.

Both countdown completion and goal-reset completion are non-goal timing events. The wire contract's generic `countdown` kind records a fresh event ID, while the resulting phase and `countdownKind` distinguish entry into the post-goal countdown from return to Active Play.

The camera defaults to Ball Camera on the first Active_Play frame, consumes monotonic C edges locally, and rebases from the interpolation frame's kickoff epoch. The indicator is pure, finite, behind-camera aware, inset-edge bounded, hidden inside the clip volume, and cannot enter the central safe zone for an accepted viewport. **Medium · confirmed:** the direct camera configuration API can nevertheless accept a non-finite value when a proposal exposes stateful properties.

## Goal-reset completion uses the generic timing-event label

`reduceMatchFlowStep` assigns a distinct sequence to `goal-reset-complete`, requests atomic kickoff placement, and produces `phase='countdown'` with `countdownKind='post-goal'`. `AuthoritativeRoomCore.advanceMatchFlowStep` records that sequence through `SnapshotBuilder.commitTransition({ kind: 'countdown' })` before committing the reducer state.

This does not lose or duplicate an outcome: the transition contains no goal or terminal payload, kickoff placement must succeed first, and the projected phase supplies the boundary's precise meaning. `MatchTransitionKind` has one non-outcome timing label, so a more specific name would be a protocol refinement rather than a current semantic fix.

## Stateful camera proposals can commit non-finite configuration

**Medium severity · confirmed.** `validatedConfiguration` checks `ball.fieldOfViewDegrees` at `client/src/renderer/camera-controller.ts:160`, then reads it again while constructing the frozen result at `client/src/renderer/camera-controller.ts:176`. `CameraController.applyConfiguration` at line 356 trusts that result as the validated complete snapshot.

A getter returning the valid default FOV on its first read and `NaN` on its second makes `applyConfiguration` return `true`. A runtime probe confirmed that the stored Ball Camera FOV, `PerspectiveCamera.fov`, and projection matrix become non-finite on the next first-Active-Play update. Snapshot every proposed scalar exactly once into plain locals, validate that snapshot, and freeze those same values; rejection must preserve the previous configuration.

## Validation and missing regression

The scoped client tests passed 25/25, shared contracts passed 15/15, and scoped server room/runtime/property/scoring tests passed 49/49. `tsc --noEmit` passed for `client`, `server`, and `shared`; `git diff --check` reported no whitespace errors.

Not tested: a camera proposal whose accessor or proxy changes a value between reads. Add a regression that returns a valid FOV once and `NaN` afterward, requires `applyConfiguration` to return `false`, preserves the prior configuration by identity, and confirms the subsequent projection matrix is finite. This exposes the confirmed defect; no missing server, terminal, toggle, kickoff-rebase, or indicator test was found that exposes another behavioral failure in the scoped diff.
