The camera configuration boundary now closes the previously confirmed time-of-check/time-of-use gap by reading each candidate node and scalar through an own-property descriptor exactly once, validating those captured primitives, and freezing the same values it publishes. Accessor-backed or descriptor-trapping proposals fail closed without replacing the last accepted configuration or changing the selected mode, and the regression proves the next camera FOV and projection matrix remain finite. The prior scoped Task 5.6 authoritative pipeline and Task 8.2 indicator assessments remain unchanged, including the generic `countdown` transition label for goal-reset completion.

## High-level view

`validatedConfiguration` now converts the untrusted proposal into a plain scalar snapshot before making an acceptance decision. The commit path consumes only that snapshot, so a proposal cannot present one value during validation and another during publication; ordinary registry and object-literal configurations retain their existing behavior.

Task 5.6 still routes both room modes through one ordered authoritative step and publishes the exact retained post-step projection through complete schema preflight. Forged authority fields remain discarded without suppressing valid controls, and goal-reset completion remains a non-goal timing event whose generic `countdown` wire label is disambiguated by the resulting phase and `countdownKind`.

Task 8.2 remains a pure presentation calculation over camera/clip space. Its finite fallback, behind-camera reflection, inset-edge containment, in-viewport hiding, resize behavior, and center-safe-zone exclusion remain covered without introducing server authority or mutable input state.

## Descriptor snapshots close the camera configuration race

The earlier implementation validated direct property reads and then read the proposal again while constructing the accepted configuration. A stateful getter could therefore return a valid FOV first and `NaN` second. `ownDataProperty` now obtains only own data descriptors, turns missing properties, accessors, and throwing descriptor traps into rejection, and `validatedConfiguration` stores each descriptor value in a local before range checks. The frozen result is built exclusively from those primitive locals, while `applyConfiguration` changes controller state only after validation succeeds.

This does not narrow an in-scope production integration. Tuning snapshots are converted to ordinary nested objects with own scalar data properties, the default configuration uses the same path, and the exported direct-update API has no production caller in this diff that depends on prototype inheritance or accessors. Rejecting those dynamic representations is the boundary behavior that prevents validation and publication from observing different values.

The new regression is sensitive to the original defect: its FOV getter would return the accepted finite value on the old validation read and `NaN` on the construction read. It now requires rejection without invoking the getter, preserves the accepted configuration by identity and the `car` mode, and then proves Ball Camera produces a finite FOV and finite projection matrix elements.

## Retained authority projection and generic countdown event remain coherent

`AuthoritativeRoomCore` retains the projection produced inside the successful fixed-step boundary, and both room adapters consume that exact artifact rather than re-reading bodies. Complete roster, ball, match, timing, occupancy, and terminal candidates are preflighted before live schema references change; input normalization allow-lists controls while ignoring forged authoritative extras.

`goal-reset-complete` receives a fresh sequence and atomic kickoff placement before the reducer enters `phase='countdown'` with `countdownKind='post-goal'`. The transition carries no goal payload, and the committed phase supplies the specific post-goal meaning, so the generic `countdown` kind preserves the protocol semantics.
